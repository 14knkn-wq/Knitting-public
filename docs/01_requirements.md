## 1. システム概要

「Knitting」は、Java 25、Spring Boot 4.0.8、Mavenを使用して開発する編み物支援Webアプリケーションです。永続データを管理する正式なデータベースにはMySQLを使用します。

編み図と実測ゲージの違いに応じた目数・段数調整、2本取り・引き揃え時の毛糸の太さと推奨針号数の概算、簡易カウンターをログインなしで利用できます。ユーザー登録・ログイン後は、作品、制作ステータス、目数・段数、制作メモ等を作品ごとに保存・管理できます。

就職活動用のポートフォリオとして開発しますが、単なる学習用アプリではなく、実際に編み物をする人が便利に使えることを目指します。

## 2. 開発目的

- 編み図と実測ゲージが異なる場合の目数・段数計算を支援する
- 2本取り・引き揃え後の毛糸の太さと推奨針号数を判断するための目安を示す
- 作品ごとの制作状況、目数・段数、制作メモを一元管理できるようにする
- ログインしなくても使える編み物支援機能を提供し、利用開始の負担を抑える
- Spring Bootを用いたWebアプリケーションの設計・実装経験を、採用担当者等の第三者へ分かりやすく示す

## 3. 想定ユーザー

- 編み図で指定された糸・針とは異なる条件で編みたい人
- 2本取りまたは引き揃えを試したい人
- 制作中・完成済みの作品を分けて管理したい人
- 作品ごとの目数・段数や制作メモを記録したい人
- ユーザー登録をせず、計算機能や簡易カウンターだけを利用したい人

## 4. 解決したい課題

### 4.1 ゲージの違いによる計算負担

編み図の指定ゲージと実際に使用する糸・針で測定したゲージが異なる場合、同程度の大きさに仕上げるための目数・段数を手作業で換算する必要があります。必要な値を入力することで、調整後の目数・段数を確認できるようにします。

### 4.2 2本取り・引き揃え時の判断

2本の毛糸を組み合わせた場合の太さや適した針号数は判断しにくいため、重量と長さから100gあたりの換算糸長を算出し、毛糸の太さと推奨針号数の目安を表示します。

### 4.3 制作情報の分散

複数の作品を制作する場合、作品情報、制作状態、現在の目数・段数、制作メモ等が分散しやすくなります。これらを作品単位で保存し、制作中作品と完成作品を分けて確認できるようにします。

### 4.4 一時的なカウント手段の不足

作品登録を行わずに目数・段数だけを数えたい場合にも使える簡易カウンターを提供し、ページ移動やブラウザ終了後も値を保持できるようにします。

## 6. 機能要件

以下のチェックボックスは、要件ごとの実装状況を表します。実装と確認が完了した項目のみ `[x]` へ変更します。

### 6.1 トップ画面

- [ ] 未ログイン時は、Knittingの概要、公開機能、ユーザー登録、ログインへの入口を表示できる
- [ ] 未ログイン時にログインを強制せず、公開機能を利用できる
- [ ] ログイン後は、ログインユーザー本人の制作中作品を表示できる
- [ ] ログイン後トップの制作中作品を最終更新日時が新しい順に表示できる
- [ ] ログイン後トップには制作中作品を最大4件表示できる
- [ ] ログイン後トップの作品に、作品写真、作品名、目数、段数を表示できる
- [ ] ログイン後トップの作品から対象作品の作品詳細へ移動できる
- [ ] ログイン後トップから作品登録と公開機能へ移動できる

### 6.2 ゲージ・目数・段数調整

- [x] 目数計算と段数計算を同じ機能内で利用できる
- [x] 目数と段数をそれぞれ独立して計算できる
- [x] 指定目ゲージ・実測目ゲージ・元の目数から調整後の目数を計算できる
- [x] 指定段ゲージ・実測段ゲージ・元の段数から調整後の段数を計算できる
- [x] ゲージはすべて10cmあたりの目数・段数として扱う
- [x] 指定ゲージと実測ゲージは小数を入力できる
- [x] 元の目数と元の段数は整数として入力できる
- [x] 指定ゲージと実測ゲージを0.01～999.99、小数第2位までの範囲で入力できる
- [x] 元の目数と元の段数を1～9999の範囲で入力できる
- [x] 目数側または段数側の3項目がすべて未入力の場合、その側は計算対象外としてエラーにしない
- [x] 計算に必要な項目の一部だけが入力された場合は、入力不足を通知する
- [x] 0以下や数値として扱えない値等を入力エラーとして扱う
- [x] 計算途中では端数処理を行わず、最終結果を四捨五入して整数で表示する
- [x] 四捨五入前の計算値を小数部最大5桁で表示し、不要な末尾0を表示しない
- [x] 四捨五入後の調整結果を整数で表示する
- [x] 計算結果が目安であり、試し編みを推奨する旨を表示する

目数と段数の基本計算は、それぞれ次の考え方を使用します。

- 調整後の目数の計算値 ＝ 元の目数 × 実測目ゲージ ÷ 指定目ゲージ
- 調整後の段数の計算値 ＝ 元の段数 × 実測段ゲージ ÷ 指定段ゲージ

模様編みの倍数等に合わせる自動調整は初期実装の対象外です。

### 6.3 2本取り・引き揃え計算

- [x] 「2本取り」と「引き揃え」を切り替えて利用できる
- [x] 2本取りでは、1本分の重量（g）と長さ（m）を入力し、同じ毛糸を2本使用したものとして計算できる
- [x] 引き揃えでは、異なる2本の毛糸について重量（g）と長さ（m）を個別に入力できる
- [x] 重量と長さは小数を入力できる
- [x] 重量と長さを0.01～99999.99、小数第2位までの範囲で入力できる
- [x] 3本以上の組み合わせには対応しない
- [x] 各毛糸の1mあたりの重量をもとに、組み合わせ後の100gあたりの換算糸長を算出できる
- [x] 換算糸長を整数へ四捨五入し、「約○m / 100g」と表示できる
- [x] 換算糸長から推定される毛糸の太さを表示できる
- [x] 推定した太さに対応する推奨棒針号数・推奨かぎ針号数を表示できる
- [ ] 計算結果から毛糸・推奨針号数対応表へ移動できる
- [x] 必要項目の空欄、0、負の値、数値として扱えない値等を入力エラーとして扱う
- [x] 必要な入力値がすべて正常な場合のみ計算できる
- [x] 重量と長さだけによる目安であることと、試し編みを推奨する注意書きを表示する

毛糸の素材、撚り、毛足、糸の構造、メーカー、商品名等は計算対象としません。毛糸の太さと推奨針は、一般的なウール系ストレートヤーンを基準とした7区分（極細・合細・中細・合太・並太・極太・超極太）から判定します。結果が一般的な目安であり、メーカー推奨情報と試し編みを優先することを案内します。

### 6.4 簡易カウンター

- [x] ログインの有無にかかわらず利用できる
- [x] 目数カウンターと段数カウンターを同じ画面に同時表示できる
- [x] 目数のみ、段数のみ、または両方を利用できる
- [x] 目数・段数の初期値を0とする
- [x] 目数・段数をそれぞれ独立して1ずつ増減できる
- [x] 目数・段数を0～9999の範囲で管理できる
- [x] 0では減少操作、9999では増加操作を行えない
- [x] 0～9999の範囲で任意の現在値を直接入力できる
- [x] 直接入力された全角数字を半角数字として扱う
- [x] 数字以外、小数、負数、9999を超える値を入力エラーとして扱う
- [x] 目数・段数を個別に0へリセットできる
- [x] 目数・段数をまとめて0へ戻す際は、実行前に確認できる
- [x] ページ移動後も値を保持できる
- [x] ブラウザを閉じた後も値を保持し、再度アクセスした際に前回の値から再開できる
- [x] 作品専用カウンターとは別の機能として扱う

目数・段数はブラウザのlocalStorageへ個別に保存し、正常値の確定時に即時更新します。localStorageを利用できない場合もページ内では使用できるようにし、保持できない可能性を案内します。簡易カウンターの値をユーザー登録後の作品へ引き継ぐ機能は、初期実装後の将来検討事項です。

### 6.5 毛糸・推奨針号数対応表

- [ ] ログインの有無にかかわらず閲覧できる
- [ ] 毛糸の太さ区分、100gあたりの長さ、推奨棒針号数、推奨かぎ針号数を1つの表で確認できる
- [ ] スマートフォンでも表形式を維持し、画面幅に収まらない場合は横スクロールして確認できる
- [ ] 表示値が目安であり、毛糸の商品表示がある場合はメーカーの推奨情報を優先する旨を表示する
- [ ] 2本取り・引き揃え計算結果から直接移動できる

初期実装では対応表を1種類とし、表の切り替え、検索、絞り込みは設けません。一般的なウール系ストレートヤーンを基準に、極細から超極太までの7区分を太い順ではなく「極細、合細、中細、合太、並太、極太、超極太」の順で表示し、S-05の判定と同じ100gあたりの長さ・推奨棒針・推奨かぎ針の基準を使用します。

### 6.6 ユーザー登録

- [x] メールアドレス、ユーザー名、パスワード、確認用パスワードを入力して登録できる
- [x] すべての項目を必須入力として扱う
- [x] メールアドレスの形式を確認し、登録済みメールアドレスの重複を許可しない
- [x] メールアドレスを小文字へ正規化して保存し、大文字・小文字だけが異なる入力を同一メールアドレスとして扱う
- [x] ユーザー名を4文字以上20文字以下の半角英数字として扱う
- [x] 登録済みユーザー名の重複を許可しない
- [x] ユーザー名の重複判定では大文字・小文字を区別しない
- [x] パスワードを8文字以上64文字以下として扱う
- [x] パスワードを印字可能なASCII文字として扱い、制御文字・非ASCII文字を受け付けない
- [x] パスワードと確認用パスワードの一致を確認する
- [x] 推測されやすいパスワードをローカルのPassword Blocklistに基づいて拒否する
- [x] パスワードと確認用パスワードの表示・非表示を切り替えられる
- [x] 項目ごとに入力エラーを表示し、エラーがある場合は登録できない
- [x] 登録完了後は自動ログインせず、登録完了の案内を表示してログイン画面へ移動する

ユーザー名は、半角英字だけ、半角数字だけ、または両方の組み合わせを使用できます。登録時の表記は表示用として保持し、重複判定とログイン時は大文字・小文字を区別しません。パスワードに特定の文字種を含めることは必須とせず、前後空白の除去や文字の正規化も行いません。初期実装ではパスワード再設定機能を設けません。

### 6.7 ログイン・自動ログイン・ログアウト

- [x] ユーザー名とパスワードでログインできる
- [x] ログイン時のユーザー名は大文字・小文字を区別せず照合できる
- [x] メールアドレスは初期実装のログインIDとして使用しない
- [x] 未入力項目がある場合は項目ごとにエラーを表示し、ログインできない
- [x] 認証失敗時は、原因を個別に特定しない共通メッセージを表示する
- [x] パスワードの表示・非表示を切り替えられる
- [x] ログイン成功後はログイン後トップ画面へ移動する
- [x] ユーザーが自動ログインの利用有無を選択できる
- [x] 自動ログインを選択した場合は30日間ログイン状態を保持できる
- [x] 自動ログインの有効期間を利用のたびに延長しない
- [x] ログイン中は共通ナビゲーションからログアウトできる
- [x] 明示的なログアウト時は自動ログイン状態も解除する
- [x] ログアウト後は未ログイン状態のトップ画面へ移動する

認証・認可にはSpring Securityを使用します。通常の認証状態はセッションで保持し、自動ログインにはDBテーブルを追加しないトークン方式を使用します。明示的なログアウト時は現在の端末のセッションと自動ログイン状態を終了します。

### 6.8 作品登録

- [ ] ログインユーザーが自分の作品を登録できる
- [ ] 作品名を1文字以上50文字以下の必須入力として登録でき、同一ユーザー内で同じ作品名の重複を許可する
- [ ] カテゴリーを必須項目として1つ選択できる
- [ ] 作品写真を任意で1枚登録できる
- [ ] 写真が登録されていない場合はKnittingで用意する初期画像を使用する
- [ ] 制作ステータスを「制作中」または「完成」から選択できる
- [ ] 制作ステータスの初期値を「制作中」とする
- [ ] 必須項目にエラーがある場合は項目ごとに通知し、正常になるまで登録できない
- [ ] 登録完了後は登録した作品の作品詳細へ移動する

初期実装のカテゴリーは「帽子・上衣・下衣・マフラー・バッグ・ぬいぐるみ・小物・その他」とします。目数・段数および制作メモは登録時には入力せず、登録後の作品詳細で管理します。作品写真はJPEGまたはPNG、10MiB以下、幅・高さ8192px以下を受け付け、保存時はアスペクト比を保ったまま長辺を最大1920pxへ縮小します。

### 6.9 作品詳細・作品情報編集

- [ ] ログインユーザーが自分の作品情報を確認できる
- [ ] 作品名、作品写真、カテゴリーを後から編集できる
- [ ] 作品名、作品写真、カテゴリーは通常時に閲覧状態とし、編集操作後のみ変更できる
- [ ] 作品名、作品写真、カテゴリーの変更は、保存操作を行った場合のみ確定できる
- [ ] 編集中の変更をキャンセルできる
- [ ] 作品写真を変更・削除でき、削除後は初期画像を使用する
- [ ] 制作中・完成のどちらの作品も編集できる
- [ ] 制作中一覧または完成一覧から作品詳細へ移動した場合は、作品詳細で制作ステータスを変更しても遷移元一覧へ戻ることができる
- [ ] 遷移元一覧の情報がない場合は、現在の制作ステータスに対応する一覧へ戻ることができる
- [ ] 作品基本情報の編集中に保存せず画面を離れる場合は、未保存変更の確認を表示できる
- [ ] 未保存変更がある状態でログアウトする場合は、ログアウト確認と未保存警告を1つの確認にまとめて表示できる

### 6.10 作品専用カウンター

- [ ] 作品詳細で目数と段数の2つのカウンターを同時表示できる
- [ ] 目数・段数の初期値を0とする
- [ ] 作品ごとに目数・段数を0～9999の範囲で保持できる
- [ ] 目数・段数をそれぞれ1ずつ増減できる
- [ ] 0では減少操作、9999では増加操作を行えない
- [ ] 0～9999の範囲で任意の現在値を直接入力できる
- [ ] 直接入力された全角数字を半角数字として扱う
- [ ] 数字以外、小数、負数、9999を超える値を入力エラーとして扱う
- [ ] カウンター変更を自動保存できる
- [ ] 制作中・完成のどちらでもカウンターを利用できる

目数・段数は画面上の値を即時に更新し、最後の操作から300ms後に非同期保存します。

### 6.11 制作メモ

- [ ] 作品ごとに1つの制作メモを保持できる
- [ ] 制作メモを任意入力の自由記述として扱う
- [ ] 制作メモを最大1000文字まで入力できる
- [ ] 制作中・完成のどちらでも編集できる
- [ ] 制作メモを自動保存できる

制作メモは最後の入力から1秒間操作がない場合に非同期保存します。

### 6.12 制作ステータス・完成日

- [ ] 制作ステータスを「制作中」と「完成」の間で変更できる
- [ ] 制作ステータスの変更を自動保存できる
- [ ] 作品を「完成」にした日付を完成日の初期値として設定できる
- [ ] 登録時から「完成」の場合は、登録時の日付を完成日の初期値として設定できる
- [ ] 完成日を年月日単位で扱い、後から任意の日付へ変更できる
- [ ] 完成日に未来の日付を設定できないようにする
- [ ] 完成日の変更を自動保存できる
- [ ] 完成作品を「制作中」へ戻した場合、以前の完成日を現在の完成日として使用しない
- [ ] 再度「完成」へ変更した場合は、再完成日を新しい完成日の初期値として設定できる
- [ ] 過去の完成日履歴は初期実装では管理しない

### 6.13 最終更新日時

- [ ] 制作中作品の並び順に使用する最終更新日時を管理できる
- [ ] 目数、段数、制作メモ、作品名、写真の変更・削除、カテゴリー、制作ステータスの変更を更新として扱う
- [ ] 作品詳細を閲覧しただけでは最終更新日時を変更しない
- [ ] 完成日の手動変更だけでは最終更新日時を変更しない

最終更新日時はアプリケーション側で管理し、値が実際に変わった場合のみ更新します。同じ値の再送では更新しません。

### 6.14 制作中一覧

- [ ] ログインユーザー本人の「制作中」作品だけを一覧表示できる
- [ ] 作品写真、作品名、目数、段数を作品カードとして表示できる
- [ ] 写真未登録作品には初期画像を表示できる
- [ ] 作品カードから対象作品の作品詳細へ移動できる
- [ ] カテゴリーで絞り込める

## 7. データ要件

システムが保持する主要な情報を要件レベルで示します。永続データを管理するデータベースにはMySQLを使用します。初期版の具体的なテーブル構成、データ型、関連および制約は `04_database-design.md` で定義済みです。本書では、それらの物理仕様を転記せず、システムが保持すべき情報を示します。

初期版では、1人のユーザーが0件以上の作品を所有でき、1作品は必ず1人のユーザーに属するものとします。作品基本情報と現在の制作情報を作品単位で保持し、制作履歴、カウンター履歴、制作メモ履歴および完成日履歴は保持しません。

## 8. 非機能要件

機能ごとの入力範囲、保存・保持方法、認証・エラー処理の基本方針は本書の要件として確定済みです。公開時の性能目標や運用環境に依存する数値は、公開環境決定後に確定します。

### 8.1 使用性

- 編み物をするユーザーが入力項目と計算結果を理解しやすい構成とする
- PC・スマートフォンの両方で利用できる構成とする
- スマートフォンの作品一覧は1列表示とする
- 対応表はスマートフォンでも表形式を維持し、必要に応じて横スクロールできるようにする
- 計算結果や対応表が目安である場合は、その旨を分かりやすく表示する
- 頻繁に変更する作品情報は自動保存し、作品基本情報は保存・キャンセル方式として使い分ける

### 8.2 正確性・信頼性

- 決定した計算式に対し、想定した結果が得られることをテストする
- 入力できない値や計算できない値を適切に検出する
- 自動保存対象の変更が失われないようにする
- 初期版で確定したデータ構造・制約に従ってデータの整合性を保つ
- 作品詳細の自動保存は同一項目の同時更新競合を検出し、競合した変更を自動統合・自動再送しない
- 自動保存の通信失敗・サーバーエラー時は保存失敗を表示し、ユーザー操作で再試行できるようにする

### 8.3 セキュリティ

- 他のユーザーの作品を閲覧・変更できないようにする
- Spring Securityを使用し、フォームログイン、ログアウト、アクセス制御、CSRF対策、セッション管理、自動ログインを行う
- 平文パスワードと確認用パスワードは保存せず、認証に必要なハッシュ化済み情報のみを保存する
- パスワードはSpring Securityの委譲型エンコーダーを使用し、初期方式をbcryptとする
- 公開前にログイン・ユーザー登録へのRate Limitを導入する
- 本番公開ではHTTPSを必須とし、認証情報・秘密情報をソースコードやGitへ保存しない

### 8.4 性能

- 想定利用者数、応答時間、同時アクセス数は未定
- ポートフォリオとして必要以上に大規模・複雑な構成にはしない

### 8.5 保守性

- 仕様変更と実装状況に合わせてREADMEおよび設計書を更新する
- 初心者がSpring Bootを学習しながら理解・保守できる規模と構成にする
- Spring MVCとThymeleafによるサーバーサイドレンダリングを基本とし、必要最小限のJavaScriptを使用する
- Spring Data JPAで永続化し、FlywayのマイグレーションをDBスキーマの正本とする

### 8.6 可用性・運用

- 公開方法、稼働時間、バックアップ、監視、障害時対応は未定
- 入力エラー、業務エラー、システムエラーを区別し、400・403・404・500の共通エラー画面を使用する
- 予期しないシステムエラーでは内部情報をユーザーへ表示しない

## 9. 制約事項

- 使用言語はJava 25とする
- フレームワークはSpring Boot 4.0.8とする
- ビルドツールはMavenとする
- 開発にはEclipseを使用する
- データベースにはMySQLを使用する
- MySQL Community 8.4 LTS系列、文字コードutf8mb4、基本照合順序utf8mb4_0900_ai_ciを使用する
- WebはSpring MVC、画面描画はThymeleaf、フロントエンドはHTML・CSS・必要最小限のJavaScriptとする
- 永続化にSpring Data JPA／Hibernate、DBマイグレーションにFlywayを使用する
- 認証・認可にはSpring Securityを使用する
- バージョン管理にはGitを使用し、GitHubで管理する
- 2本取り・引き揃え計算は重量と長さのみを使用し、素材・撚り・毛足等を考慮しない
- 2本取り・引き揃え計算は最大2本までとし、初期実装では3本以上に対応しない
- 毛糸の太さ、推奨針号数および対応表は目安として提供する
- 対応表は一般的なウール系ストレートヤーンを基準とする7区分の確定値を使用する
- 初期実装ではパスワード再設定機能を設けない
- 初期実装では過去の完成日履歴を管理しない
- 初期実装では計算機能一覧画面を設けない
- 初心者がSpring Bootを学習しながら開発するため、必要以上に大規模・複雑なシステムにはしない
