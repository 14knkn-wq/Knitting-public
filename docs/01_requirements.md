## 1. システム概要

「Knitting」は、Spring Bootを使用して開発する編み物支援Webアプリケーションです。

編み図と異なる糸を使う場合の目数・段数調整、2本取り・引き揃え時の概算、作品・進捗・制作メモの管理を支援します。就職活動用のポートフォリオとして開発しますが、実際に編み物をする人が便利に使えることを目指します。

## 2. 開発目的

- 編み物で必要となる計算の手間を減らす
- 計算結果を目安として示し、異なる糸を使う際の検討を支援する
- 制作中の作品情報と進捗を作品ごとに管理できるようにする
- Spring Bootを用いたWebアプリケーションの設計・実装経験を示す
- 採用担当者などの第三者が、設計意図と開発進捗を確認できる状態にする

## 3. 想定ユーザー

- 編み図で指定された糸とは異なる糸を使いたい人
- 2本取りまたは引き揃えを試したい人
- 制作中の作品、目数、段数、進捗、メモをまとめて管理したい人

ユーザーの年齢、編み物経験、利用端末などの詳細な想定は要検討です。

## 4. 解決したい課題

### 4.1 ゲージの違いによる計算

編み図の指定ゲージと実際に使用する糸のゲージが異なる場合、必要な目数・段数を手作業で換算する必要があります。計算に不慣れなユーザーでも、必要な値を入力することで調整後の目安を確認できるようにします。

### 4.2 2本取り・引き揃え時の判断

糸を2本組み合わせたときの太さや適した針号数は判断しにくいため、重量と長さから概算値を表示します。ただし、素材・撚り・毛羽立ちなどによる差は計算に含めません。

### 4.3 作品ごとの制作情報の管理

制作中の作品が複数ある場合、使用糸、使用針、現在の段数、制作メモなどが分散しやすくなります。これらを作品単位で保存・確認できるようにします。

## 5. 機能要件

以下のチェックボックスは要件ごとの実装状況を表します。現時点ではすべて未実装です。実装と確認が完了した項目を `[x]` に変更します。

### 5.1 ゲージ・目数・段数調整機能

- [ ] 編み図で指定されたゲージを入力できる
- [ ] 使用する糸で実測したゲージを入力できる
- [ ] 元の目数を入力できる
- [ ] 指定ゲージと実測ゲージをもとに、調整後の目数の目安を計算できる
- [ ] 元の段数を入力できる
- [ ] 指定ゲージと実測ゲージをもとに、調整後の段数の目安を計算できる
- [ ] 計算結果を画面に表示できる

#### 入力・計算例

| 項目 | 値 |
| --- | ---: |
| 指定ゲージ | 10cm = 20目 |
| 指定目数 | 100目 |
| 実測ゲージ | 10cm = 16目 |
| 調整後の目数の目安 | 80目 |

調整後の目数は、同じ寸法を保つために、元の目数へ「実測ゲージ ÷ 指定ゲージ」の比率を掛けて求める想定です。段数も同じ考え方で計算する予定です。

次の詳細は要検討です。

- 小数が発生した場合の丸め方
- 模様編みなど、目数・段数に一定の倍数が必要な場合の扱い
- 入力可能な値の範囲
- 10cm以外のゲージ表記へ対応するか

### 5.2 2本取り・引き揃え計算機能

- [ ] 糸1本につき重量（g）を入力できる
- [ ] 糸1本につき長さ（m）を入力できる
- [ ] 同じ糸を2本使用する「2本取り」を計算できる
- [ ] 異なる糸を組み合わせる「引き揃え」を計算できる
- [ ] 最大2本までの糸を組み合わせられる
- [ ] 重量と長さをもとに、糸ごとの線密度などの計算に必要な値を算出できる
- [ ] 組み合わせ後の換算重量・長さを表示できる
- [ ] 組み合わせ後の推定糸太さを表示できる
- [ ] 推奨棒針号数を表示できる
- [ ] 推奨かぎ針号数を表示できる
- [ ] 概算であることと試し編みを推奨する注意事項を表示できる

#### 計算上の前提

- 入力情報は重量（g）と長さ（m）のみとする
- 素材、撚り、毛羽立ちなどは考慮しない
- 計算結果は厳密な値ではなく、目安として扱う
- 初期バージョンでは3本以上の組み合わせに対応しない

画面には、次の趣旨の注意事項を表示する予定です。最終的な文言は要検討です。

> 素材・撚り・毛羽立ちなどは考慮していない概算です。実際に使用する際は試し編みを推奨します。

次の詳細は要検討です。

- 線密度および換算重量・長さの最終的な計算式
- 糸の太さを分類する基準と表示名称
- 推定糸太さから棒針・かぎ針号数へ換算する基準
- 境界値に該当する場合の表示方法
- 入力画面と結果画面の構成

### 5.3 作品管理機能

- [ ] 作品を登録できる
- [ ] 登録した作品を一覧表示できる
- [ ] 作品の詳細を表示できる
- [ ] 作品情報を編集できる
- [ ] 作品を削除できる

#### 管理予定の情報

- [ ] 作品名
- [ ] 使用糸
- [ ] 使用針
- [ ] 目数
- [ ] 現在の段数
- [ ] 目標段数
- [ ] 制作ステータス

各項目の必須・任意、文字数、入力形式、制作ステータスの選択肢は要検討です。削除時の確認方法や、削除した情報を復元できるようにするかも未定です。

### 5.4 目数・段数カウンター

- [ ] 作品ごとに現在の目数を記録できる
- [ ] 作品ごとに現在の段数を記録できる
- [ ] 「＋」操作で目数・段数を増やせる
- [ ] 「－」操作で目数・段数を減らせる
- [ ] 現在の段数と目標段数を表示できる
- [ ] 現在の段数と目標段数をもとに進捗率を表示できる

進捗率は「現在の段数 ÷ 目標段数 × 100」で求めることを検討しています。小数点以下の表示桁数、100%を超えた場合の扱い、目数を進捗率に使用するかは要検討です。

表示例：

- 現在：34段
- 目標：80段
- 進捗：約42.5%

### 5.5 制作メモ

- [ ] 作品ごとに制作メモを登録できる
- [ ] 登録した制作メモを表示できる
- [ ] 制作メモを編集できるか検討する
- [ ] 制作メモを削除できるか検討する
- [ ] 制作メモと段数カウンターを関連付けるか検討する

メモの入力形式、文字数、登録件数、日時の記録、段数との関連付け方法は要検討です。

メモ例：

- 36段目：減らし目開始
- 42段目：糸を変更

### 5.6 ユーザー機能

- [ ] ログアウトできる

認証方式、登録情報、パスワードに関する仕様、ユーザー情報の編集・削除を実装するかは未定です。

## 6. 非機能要件

非機能要件の具体的な数値や対応範囲は、今後の設計で決定します。

### 6.1 使用性

- 編み物をするユーザーが入力項目と計算結果を理解しやすい画面を目指す
- 計算結果が概算である場合は、その旨を分かりやすく表示する
- 対応端末、画面サイズ、対象ブラウザは要検討

### 6.2 正確性・信頼性

- 決定した計算式に対して、想定どおりの結果が得られることをテストする
- 不正または計算できない入力値をどのように扱うかは要検討
- データ保存時の整合性に関する具体的な要件は要検討

### 6.3 セキュリティ

- ユーザー機能の実装後は、他のユーザーの作品を操作できないようにする
- 認証方式、パスワードの取り扱い、セッション管理などの詳細は要検討

### 6.4 性能

- 想定する利用者数、応答時間、同時アクセス数は未定
- ポートフォリオとして過度に大規模・複雑な構成にはしない

### 6.5 保守性

- 設計変更や実装状況に合わせて、READMEと設計書を更新する
- 初心者が学習しながら理解・保守できる規模と構成にする
- 具体的なアプリケーション構成や設計方式は要検討

### 6.6 可用性・運用

- 公開方法、稼働時間、バックアップ、監視、障害時の対応は未定

## 7. 制約事項

- 使用言語はJavaとする
- フレームワークはSpring Bootとする
- 開発にはEclipseを使用する
- バージョン管理にはGitを使用し、GitHubで管理する
- 2本取り・引き揃え計算の入力は、糸1本につき重量（g）と長さ（m）のみとする
- 2本取り・引き揃え計算では、素材、撚り、毛羽立ちなどを考慮しない
- 2本取り・引き揃え計算は最大2本までとし、初期バージョンでは3本以上に対応しない
- 糸の太さと推奨針号数は概算として表示する
- 初心者がSpring Bootを学習しながら開発するため、必要以上に大規模・複雑なシステムにはしない
- Java、Spring Boot、Eclipse、Git、GitHub以外の技術は現時点では確定していない
